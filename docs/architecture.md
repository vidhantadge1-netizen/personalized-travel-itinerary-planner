# Architecture

The project is split into three parts:

- `frontend/` — React + Vite user interface
- `backend/` — FastAPI API
- `docs/` — college project notes

## Request flow

1. The student fills a trip form in the React app.
2. The frontend sends JSON to FastAPI (`POST /itineraries`).
3. FastAPI validates the request with Pydantic.
4. `itinerary_service` asks the AI factory for a provider.
5. The factory currently returns `MockAIProvider` (no API key).
6. The mock plan is generated by the AI adapter (mock for now).
7. If `backend/.env` has a publishable key **and** `trips` / `itineraries`
   pass a read/schema check, FastAPI saves and loads rows in Supabase.
8. Otherwise the API keeps an in-memory copy so the UI still works.

```text
React (Vite) --> FastAPI --> itinerary_service --> AI factory --> mock provider
                     |
                     +--> Supabase (only after schema + read access check)
```

## AI provider independence

Routers never import OpenAI, Gemini, or any vendor SDK.

- `backend/ai/base.py` defines the `AIProvider` interface
- `backend/ai/mock_provider.py` implements it for local demos
- `backend/ai/factory.py` chooses a provider from `AI_PROVIDER`

To add a real model later, create another class with the same
`generate_itinerary` method and register it in the factory.
